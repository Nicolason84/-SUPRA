## 3. Périmètre de SUPRA GOVERNANCE

### 3.1 Dans le Périmètre

SUPRA GOVERNANCE doit :
- Activer le système de Gates (G1 à G5) comme processus opérationnel
- Implémenter le registre ADR et le rendre actif
- Automatiser la vérification de conformité à la Constitution
- Mettre en place la surveillance des zones protégées
- Définir les métriques de gouvernance
- Créer les rapports périodiques de gouvernance
- Établir le processus de revue trimestrielle
- Activer SUPRA-Governance comme agent dédié
- Former les agents aux règles constitutionnelles
- Documenter les procédures opérationnelles

### 3.2 Hors du Périmètre

SUPRA GOVERNANCE ne doit pas :
- Modifier la Constitution (amendement uniquement)
- Développer de nouvelles fonctionnalités Runtime
- Créer de nouveaux plugins
- Implémenter Theory Engine, Sherpa ou Cortex
- Modifier le code existant (sauf pour la gouvernance)
- Supprimer des fichiers

## 10. Critères de Succès

SUPRA GOVERNANCE sera terminée uniquement si :

1. **Gates opérationnels** : Les 5 Gates (G1-G5) sont documentés et peuvent être exécutés
2. **Registre ADR actif** : ADR_REGISTRY.json existe et contient les ADR fondatrices
3. **Vérification de conformité** : Un processus de vérification est en place
4. **Surveillance des zones protégées** : Les modifications des zones protégées sont tracées
5. **Rapports de gouvernance** : Un template de rapport périodique est défini
6. **Agent de gouvernance** : SUPRA-Governance est défini (ou intégré à Architect)
7. **Procédures documentées** : Les procédures opérationnelles sont rédigées
8. **Formation dispensée** : Les agents connaissent les règles constitutionnelles
9. **Validation passée** : Audit de conformité réussi
10. **Rapport exécutif produit** : Rapport final livré

## 12. Recommandations

1. **Commencer par les Gates** : Activer G1-G5 en priorité — c'est le cœur du système de gouvernance
2. **Automatiser progressivement** : Commencer avec des checklists manuelles, automatiser quand le besoin est clair
3. **Ne pas surcharger** : La gouvernance doit faciliter, pas bloquer
4. **Former avant de sanctionner** : Les agents doivent comprendre les règles avant d'être jugés
5. **Itérer** : La gouvernance est un processus vivant, pas un ensemble de règles figées
6. **S'appuyer sur SUPRA-Auditor** : L'auditeur est l'allié naturel de la gouvernance
7. **Garder le Single Writer Rule** : Même la gouvernance doit passer par Builder pour écrire
