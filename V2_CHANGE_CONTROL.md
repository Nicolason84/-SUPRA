## 1. PURPOSE

This protocol governs all changes made during the V2 development cycle. It ensures that every modification is isolated, traceable, reversible, and backed by measurable evidence.

---

## 2. CHANGE CLASSIFICATION

| Class | Description | Approval Required | Examples |
|-------|-------------|-------------------|----------|
| **PATCH** | Bug fix, no functional change | None (self-certifying) | Fix nil crash, correct typo |
| **MINOR** | Additive change, backward-compatible | Executive approval | New Codable field, new feature behind flag |
| **MAJOR** | Breaking change to schema/contract | Executive override (constitutional) | Schema version bump, type removal |
| **EMERGENCY** | Critical fix under time pressure | Post-hoc Executive ratification | Security fix, data loss prevention |

## 3. CHANGE LIFECYCLE

Every change follows this lifecycle:

```
PROPOSAL
    │  (Describe: what, why, evidence)
    ▼
CLASSIFICATION
    │  (PATCH | MINOR | MAJOR | EMERGENCY)
    ▼
APPROVAL
    │  (Per classification authority)
    ▼
IMPLEMENTATION
    │  (Builder writes code)
    ▼
VERIFICATION
    │  (Build + Tests + Validation gates)
    ▼
CERTIFICATION
    │  (FACTORY_06 certifies output)
    ▼
MERGE
    │  (Commit to executive-runtime-v2)
    ▼
DOCUMENTATION
    │  (CHANGELOG entry, evidence recorded)
    ▼
COMPLETE
```

## 5. ROLLBACK PROCEDURE

### Standard Rollback
```bash
git checkout BUILD_CERTIFIED_V1
xcodebuild -project SUPRA.xcodeproj -scheme SUPRA build
xcodebuild -project SUPRA.xcodeproj -scheme SUPRA test
```

### Partial Rollback (single feature)
```bash
git revert <commit-hash>
# Verify no regression on other features
xcodebuild test
```

### Emergency Rollback
```bash
git checkout BUILD_CERTIFIED_V1 -b emergency-rollback-$(date +%Y%m%d-%H%M%S)
```
